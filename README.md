# RibkaYoga

Конструктор последовательностей асан для автора практик и преподавателя. Laravel хранит данные и изображения, Vue предоставляет библиотеку и редактор. Это один модульный монолит с одной PostgreSQL-базой и одним циклом развёртывания.

## Что доступно

- Отдельные аккаунты владельца и преподавателя в общем рабочем пространстве. Публичная регистрация отключена.
- Библиотека готовых изображений: пакетная загрузка, одинаковые поля создания и редактирования карточки (название, другие названия, категории, заметка, изображение), поиск с обработкой е/ё, русская алфавитная сортировка, архив.
- Категории — простой плоский список без подкатегорий и тегов. В текущем пространстве добавлены примеры «Стоя», «Сидя» и «Лёжа»; категории можно создавать и переименовывать.
- Подборки асан с ручным порядком и повторным использованием в редакторе.
- В разделе «Сохранённые строки» можно создать строку с нуля: кнопка «Создать строку» доступна при пустом и заполненном списке. Новая строка открывается в отдельном редакторе с шестью пустыми ячейками.
- Практика → блоки → строки → ячейки. Новая практика содержит пять блоков, по одной строке с шестью пустыми ячейками. Структура редактируется.
- Вставка карточек, drag-and-drop и альтернативные действия нажатием, подписи и заметки, отмена и повтор, сохранение и обнаружение конфликта между окнами.
- Компактные квадратные ячейки до 12 в строке, добавление через «+», окно выбора картинки либо собственного названия по нажатию.
- Группы со скобками: кнопка «Объединить», выбор первой и последней ячейки одной строки, подтверждение. В редакторе ячейки группы жёлтые, внешние боковые грани крайних ячеек — ярко-жёлтые. На готовом листе и печати группу ограничивают квадратные скобки. Доступны снятие группировки и отмена действия.
- Независимые копии практик, шаблоны и сохранённые строки. Снимки карточек сохраняют прежнее название и изображение даже после изменения каталога.
- Чистый просмотр, печать A4 и PDF через диалог печати браузера.

В текущую локальную библиотеку импортирована **71 карточка**, вырезанная из предоставленного пользователем листа. У **34 карточек** название содержит пометку «уточнить»: такие подписи следует проверить с преподавателем и отредактировать в библиотеке. Источник указан в описаниях. Подготовленные изображения и манифест находятся в `resources/imports/reference-sheet/`.

Для новой установки доступен отдельный импорт через `ribka:import-asanas`; повторный запуск пропускает ранее импортированные карточки и сохраняет пользовательские правки. Скрипт запуска приложения не выполняет импорт автоматически. Формат и команды описаны в [docs/IMPORT_ASANAS.md](docs/IMPORT_ASANAS.md). Собственные изображения также можно загрузить через интерфейс.

## Стек и версии

На момент сборки в lock-файлах зафиксированы Laravel **13.33.0**, Fortify **1.40.0**, Inertia Laravel **3.4.0**, Vue **3.5.43**, Inertia Vue **3.7.1**, Vite **8.3.1**, TypeScript **5.9.3**, Tailwind **4.3.3**. Источник точных версий зависимостей — `composer.lock` и `package-lock.json`; используйте `composer install` и `npm ci`.

Контейнеры: PHP **8.4 FPM**, PostgreSQL **17**, Nginx **1.28**, Node.js **24**, Composer **2**. PHP содержит PostgreSQL, GD с PNG/JPEG/WebP, Intl, ZIP и OPcache. Патч-версии Docker-образов определяются их тегами в `compose.yaml` и Dockerfile. Для воспроизводимого production-развёртывания образы следует отдельно закрепить по digest.

## Локальный запуск в Windows

Нужны Docker Desktop с запущенным Linux engine, Docker Compose v2 с поддержкой `--wait` и PowerShell. PHP, Composer, Node.js и PostgreSQL на Windows устанавливать не требуется. Docker Desktop должен иметь доступ к каталогу проекта. При первом запуске понадобится доступ к реестрам образов, Composer и npm.

Из каталога проекта:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\start.ps1
```

Скрипт создаёт `.env` из `.env.example` **только при его отсутствии**, генерирует случайные `APP_KEY` и пароль БД, собирает PHP-образ, запускает PostgreSQL, устанавливает зависимости из lock-файлов, применяет новые миграции, собирает frontend и запускает приложение. Затем проверяет `/up` и `/login`.

Адрес по умолчанию: **http://localhost:8080**. Веб-порт привязан только к `127.0.0.1`. Для другого порта измените `APP_PORT` и `APP_URL` в `.env`, затем повторите запуск.

Существующий `.env` и база не перезаписываются. Скрипт останавливается при ошибке; частично выполненный запуск не требует сброса данных — исправьте причину и запустите снова. Пользователи автоматически не создаются. Если для текущей локальной установки подготовлен `.runtime/local-access.txt`, учётные данные находятся в этом локальном файле; он исключён из Git. Не публикуйте его.

Остановка с сохранением базы, файлов и зависимостей:

```powershell
.\scripts\stop.ps1
```

Повторный быстрый запуск уже установленной версии:

```powershell
docker compose up -d --wait app web
```

После изменений зависимостей, миграций или frontend запускайте полный `scripts/start.ps1`.

## Linux, macOS и WSL

Нужны Docker Engine/Desktop, Compose v2 и `openssl` для первоначальной генерации секретов:

```sh
sh scripts/start.sh
```

Этот скрипт выполняет те же шаги, сохраняет существующий `.env` и проверяет HTTP-ответ приложения. Остановка:

```sh
docker compose stop
```

Исходники смонтированы в контейнеры. PostgreSQL, `vendor` и `node_modules` находятся в именованных Docker volumes. Приватные изображения сохраняются в `storage/app/private` в каталоге проекта. Команда `docker compose down` сохраняет volumes, но для повседневной остановки достаточно `stop`. **Не используйте `down -v`, `migrate:fresh`, `db:wipe` или ручное удаление storage для обновления приложения.**

## Первый владелец и преподаватель

Выполняйте команды после запуска приложения. Пароль вводится скрыто, дважды, минимум 12 символов. В командную строку пароль передавать не нужно.

```sh
docker compose exec app php artisan ribka:workspace "Моя практика" --email=author@example.com --user="Автор"
```

Команда напечатает UUID нового рабочего пространства. Используйте его для отдельного аккаунта преподавателя:

```sh
docker compose exec app php artisan ribka:member WORKSPACE_UUID --email=teacher@example.com --user="Преподаватель" --role=editor
```

Оба участника работают с общими асанами, подборками и практиками. Один пользователь принадлежит одному пространству. Роли первой версии: `owner` и `editor`. Управление аккаунтами выполняет оператор через Artisan; интерфейса приглашений нет.

Административный сброс пароля без почтового сервиса:

```sh
docker compose exec app php artisan ribka:password teacher@example.com
```

Активные сеансы этого аккаунта и старые remember-токены сбрасываются. Для контролируемого первоначального развёртывания команды также поддерживают окружение `RIBKA_INITIAL_PASSWORD`; не записывайте его в репозиторий, `.env.example`, shell history или общедоступные журналы. Обычный интерактивный ввод предпочтительнее.

## Модули и границы данных

| Модуль | Ответственность | Публичный контракт |
| --- | --- | --- |
| `Access` | Аккаунты, пространства и членство | `WorkspaceContext::id()`, `userId()`, `details()` |
| `Media` | Проверка, приватное хранение и выдача файлов | `AssetStore::store()`, `get()`, `getMany()`, `discardUnattached()` |
| `Catalog` | Асаны, алиасы, плоские категории, поиск и архив | `AsanaReader::findMany()` |
| `Collections` | Подборки и порядок карточек | Авторизованные HTTP-маршруты `/api/collections` |
| `Practices` | Документы, снимки карточек, блоки, строки, ячейки, шаблоны | Авторизованные HTTP-маршруты `/api/practices`, `/api/row-templates`, `/api/editor/cards/resolve` |

Бизнес-код находится в `app/Modules`, frontend — в `resources/js/modules`, общие компоненты — в `resources/js/shared`. Модуль владеет своими моделями и таблицами. Межмодульные операции выполняются через контейнер Laravel и публичные контракты, без HTTP-запросов приложения к самому себе и без импорта чужих Eloquent-моделей.

Пространство определяется из авторизованного пользователя на сервере. Каталог, подборки, документы, снимки и изображения проверяются на принадлежность пространству. Сохранение использует ожидаемую версию; при конфликте сервер возвращает 409. Изображения неизменяемы: замена создаёт новый asset, архивирование асаны не удаляет изображения старых листов.

## Настройки и изображения

Для явного административного импорта подготовленных локальных карточек есть команда `ribka:import-asanas`. Формат манифеста, проверка владельца и повторный запуск без изменения ранее импортированных карточек описаны в [docs/IMPORT_ASANAS.md](docs/IMPORT_ASANAS.md).

Основные значения находятся в `.env.example`; реальные секреты хранятся только в `.env`. Для текущего локального HTTP-запуска `SESSION_SECURE_COOKIE=false`. При отдельном HTTPS-развёртывании настройте домен, cookies, закрытый storage, резервные копии и секреты под своё окружение.

Поддерживаются **PNG, JPEG, WebP**, до **10 МБ** и **25 мегапикселей** на файл, до 30 файлов за действие в интерфейсе. Каждый файл загружается отдельно; ошибка одного файла не отменяет остальные. SVG, GIF, PDF, ZIP и загрузка произвольного URL не поддерживаются.

- Лимиты приложения: `config/ribka.php`, необязательные `RIBKA_UPLOAD_MAX_KB` и `RIBKA_UPLOAD_MAX_PIXELS` в `.env`.
- PHP: `upload_max_filesize=12M`, `post_max_size=16M`, `memory_limit=512M` в `docker/php/php.ini`.
- Nginx: `client_max_body_size 16m` в `docker/nginx/default.conf`.
- Файлы: `storage/app/private/media`; произвольные имена пользователя не используются как серверные пути.
- Оригиналы и миниатюры доступны через авторизованный `/media/{id}`, с запретом публичного кеширования. `php artisan storage:link` для этих изображений не требуется.

При изменении лимитов согласуйте приложение, интерфейс, PHP и Nginx, затем пересоберите PHP-образ и перезапустите контейнеры. Не меняйте `DB_PASSWORD` у уже инициализированного PostgreSQL volume без отдельного изменения пароля внутри БД: переменная контейнера применяется при первоначальной инициализации.

## Печать и PDF

Откройте практику, дождитесь подтверждения сохранения и выберите просмотр или печать. Печатное представление скрывает элементы редактора и сохраняет пропорции изображений. В диалоге браузера выберите A4; для файла — «Сохранить как PDF». Отключите браузерные колонтитулы при необходимости. Это браузерная печать, серверной генерации PDF или PNG нет.

## Проверка качества без автоматических тестов

По правилу владельца автоматические unit, feature, integration, component и E2E-тесты и инфраструктура для них не создаются. Проверяются сборка, типы, форматирование, маршруты, миграции и ручные сценарии. `pint --test` ниже — режим проверки форматирования, а не запуск тестов приложения.

```sh
docker compose exec app composer validate --strict
docker compose exec app composer lint:check
docker compose exec app php artisan route:list
docker compose exec app php artisan migrate:status
docker compose --profile tools run --rm node npm run typecheck
docker compose --profile tools run --rm node npm run format:check
docker compose --profile tools run --rm node npm run build
```

Ручная приёмка описана в `docs/IMPLEMENTATION_PROMPT.md`: загрузка → подборка → практика → сохранение → повторное открытие → шаблоны и строки → печать. Отдельно проверяйте два аккаунта, два окна редактора, архивные карточки, мобильный экран и ошибки соединения. Перечень команд в README не означает, что все проверки выполнены после каждого изменения.

Для диагностики:

```sh
docker compose ps
docker compose logs --tail=80 app web db
```

Ошибки Laravel находятся в `storage/logs/laravel.log`. При 419 обновите сеанс входа; несохранённые изменения сначала сохраните доступным в редакторе способом, если сеанс ещё позволяет это сделать. Не отключайте CSRF для исправления ошибки входа.

## Резервные копии

Полная копия состоит из **PostgreSQL + всего `storage/app/private` + защищённой копии `.env` с APP_KEY**. Одна база без файлов не восстановит изображения. Для согласованной копии прекратите работу пользователей и остановите веб-контейнер на время выгрузки. Храните копии вне проекта и переносите их в защищённое хранилище.

Пример ручной копии в PowerShell, без передачи пароля в аргументах и без перенаправления бинарных данных через старый PowerShell:

```powershell
$backupDirectory = Join-Path (Split-Path -Parent (Get-Location).Path) ('RibkaYoga-backup-' + (Get-Date -Format 'yyyyMMdd-HHmmss'))
New-Item -ItemType Directory -Path $backupDirectory | Out-Null
docker compose stop web
try {
    docker compose exec -T db sh -c 'pg_dump -U "$POSTGRES_USER" -d "$POSTGRES_DB" -Fc -f /tmp/ribka-backup.dump'
    if ($LASTEXITCODE -ne 0) { throw 'Не удалось выгрузить PostgreSQL.' }
    docker compose cp db:/tmp/ribka-backup.dump (Join-Path $backupDirectory 'database.dump')
    if ($LASTEXITCODE -ne 0) { throw 'Не удалось скопировать дамп.' }
    Copy-Item -LiteralPath '.\storage\app\private' -Destination (Join-Path $backupDirectory 'private') -Recurse
    Copy-Item -LiteralPath '.\.env' -Destination (Join-Path $backupDirectory '.env')
} finally {
    docker compose start web
}
```

В Linux/macOS выполните те же операции: остановите `web`, создайте `pg_dump -Fc` внутри `db`, скопируйте дамп через `docker compose cp`, затем скопируйте приватный storage и `.env` и верните `web` в работу. Контейнер БД продолжает работать.

Восстановление проверяйте сначала в отдельном экземпляре: создайте пустую БД с подходящими настройками, восстановите дамп через `pg_restore`, верните приватные файлы и исходный `APP_KEY`, обеспечьте PHP доступ на запись к storage и запустите приложение. В существующую рабочую БД дамп поверх данных не импортируйте. Схему, пути и секреты копии нужно восстанавливать согласованно.

## Границы первой версии

Нет офлайн-синхронизации и гарантии восстановления несохранённой памяти после закрытия браузера. При конфликте документ не перезаписывается молча: загрузите серверную версию или сохраните локальные изменения отдельной практикой. Нет публичных ссылок, учебных заданий, оценок, оплаты, генерации тренировок, распознавания поз или совместного редактирования в реальном времени.

Окружение Docker в этом репозитории предназначено для локальной работы. Публикация Laravel на сервере, HTTPS, почта и эксплуатационная инфраструктура требуют отдельной настройки. Исходная спецификация и правила проекта: `docs/IMPLEMENTATION_PROMPT.md`, `docs/PRODUCT_PROPOSAL.md`, `AGENTS.md`.

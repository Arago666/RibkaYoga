# RibkaYoga

Последние доработки: общая страница настроек, категории асан в окне по кнопке, меню карточек, папки программ для последовательностей и мезоциклов, одновременное редактирование пяти занятий и вставка сохранённых фрагментов из окна ячейки. Обычная практика начинается с пяти пустых блоков; шаблоны практик и циклов объединены.

Конструктор последовательностей асан для автора практик и преподавателя. Laravel хранит данные и изображения, Vue предоставляет библиотеку и редактор. Это один модульный монолит с PostgreSQL в развёртывании или SQLite для локальной разработки.

## Текущая локальная установка

Путь локальной SQLite-базы задаётся в `.env`; не заменяйте существующий файл базы при обновлении. Выпуск 22 октября проверяется на отдельной копии `.runtime/implementation-20261022/development.sqlite`, исходная база и резервные копии сохранены. На macOS приложение открывается на `http://127.0.0.1:8190`; серверная установка — `http://89.169.45.24:8081`. Для этой установки доступны отдельные PHP, Composer и Node.js; Docker не обязателен.

```powershell
php artisan migrate
npm run build
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/start-local.ps1
```

Откройте http://127.0.0.1:8080. Для нового checkout сначала выполните `composer install` и `npm ci`, подготовьте `.env`, ключ приложения и пустую SQLite-базу. Команда `php artisan db:seed` восстанавливает подготовленный снимок **только в пустую базу** и при наличии локальных файлов `database/seeders/snapshot`; она не является командой обновления существующих данных. Данные, `.env` и изображения не следует публиковать в Git. Скрипт локального запуска разрешает личное аудио до 100 МБ, тело запроса до 110 МБ и обработку до 240 секунд; лимит изображений приложения остаётся 10 МБ. Скрипт не меняет базу.

## Что доступно

- Регистрация преподавателя создаёт отдельный кабинет, рабочее пространство и собственную копию базовой библиотеки. Профиль, восстановление пароля и управление доступом доступны в интерфейсе.
- Библиотека готовых изображений: одинаковые поля создания и редактирования карточки (название, другие названия, категории, изображение), поиск с обработкой е/ё, русская алфавитная сортировка, архив. Массовая загрузка временно скрыта по запросу владельца.
- Кадрирование, яркость, контраст, насыщенность, поворот, чёрно-белый режим. Рисовалка без ИИ: перо, ластик, прямые, кривые, круги и человечек с подвижными суставами; выделение, перемещение, размер, поворот, копирование, масштаб и перемещение холста. Доступны развёрнутый редактор, действия с клавиатуры и отмена/повтор, включая очистку листа.
- В режиме «Асана» (`A`) первый щелчок создаёт круглую голову, а перетаскивание задаёт её размер; дальше линии рисуются перетаскиванием либо двумя щелчками по началу и концу. Левой кнопкой можно передвинуть конец линии или изменить размер головы за её край, правой — начать новую линию от конца или края головы. Двойной щелчок по середине линии либо «Изогнуть линию» (`B`) включает изменение изгиба; «Продолжить линию» (`N`) доступно также с клавиатуры.
- «Симметрия» (`S`) отражает новые линии относительно вертикали через центр головы. Привязка показывает горизонталь, вертикаль, ось головы и угол 90° к предыдущему сегменту; `Alt` временно отключает её. Для поворота выделенного элемента выберите «Вращение» (`R`) и потяните вокруг него; точный угол задаётся с клавиатуры в поле «Поворот, °», `Shift` при вращении включает шаг 15°.
- Карточка хранит PNG и редактируемый исходник рисунка. «Редактировать рисунок» продолжает работу с его элементами; сохранение карточки применяет незавершённые правки рисунка автоматически. Черновик сохраняется в этом браузере отдельно для кабинета и карточки, предлагается к восстановлению и удаляется после успешного сохранения рисунка на сервере. Исходник и PNG можно скачать; старый JSON рисунка также открывается. Обычная замена или обработка картинки снимает связь с прежним исходником, сохраняя ранее созданные изображения практик.
- Четыре фасета с 45 точными значениями: эффект, анатомия, положение и сложность. Прежние пользовательские категории остаются отдельным плоским списком; их можно создавать и переименовывать. Теги не возвращаются.
- Общие фасетные фильтры и контекстные счётчики в библиотеке и окнах выбора, поиск по русским/санскритским/старым названиям, личное избранное и недавние асаны. Неполная разметка видна в очереди уточнения. Карточка поддерживает инструкции, методические подсказки, оборудование и связи вариантов; неподтверждённые сведения не заполняются автоматически.
- В библиотеке переключатель «Мои рисунки / Объёмные фигуры» меняет всю сетку и увеличенный просмотр. Выбор сохраняется в URL при поиске, фильтрации и переходах между страницами. Используются готовые нейтральные фигуры; при отсутствии подходящего варианта показан исходник с пояснением. Редактирование, исходники, личные настройки вставки и сохранённые практики не меняются.
- Подборки асан с ручным порядком и вложенными папками. Перенос и удаление проверяют версии, циклы и сохранность состава.
- Раздел «Шаблоны» объединяет практики, фрагменты (строки, связки, переходы) и циклы. Старые адреса сохранённых строк работают. Можно сохранить блок или выбранный непрерывный диапазон, затем вставить независимую копию.
- Практика → блоки → строки → ячейки. Новая практика содержит пять блоков, по одной строке с шестью пустыми ячейками. Структура редактируется.
- Вставка карточек, drag-and-drop и альтернативные действия нажатием, подписи и заметки, отмена и повтор, сохранение и обнаружение конфликта между окнами.
- Компактные квадратные ячейки до 12 в строке, добавление через «+», окно выбора картинки либо собственного названия по нажатию.
- Группы со скобками: кнопка «Объединить», выбор первой и последней ячейки одной строки, подтверждение. В редакторе ячейки группы жёлтые, внешние боковые грани крайних ячеек — ярко-жёлтые. На готовом листе и печати группу ограничивают квадратные скобки. Доступны снятие группировки и отмена действия.
- Независимые копии практик, шаблоны и сохранённые строки. Снимки карточек сохраняют прежнее название и изображение даже после изменения каталога.
- Группу ячеек можно сохранить как именованную связку и вставить целиком. Для асан и связок доступны связанные упрощения, усложнения и подводящие упражнения.
- Программа/цикл содержит от 1 до 52 занятий, по умолчанию пять, и необязательное облако выбранных асан. Можно добавить независимую копию готовой практики, менять порядок и названия позиций, сохранять шаблон цикла. Одновременно монтируется только активный редактор. Перетащите рисунок из облака в ячейку любой недели; на сенсорном экране используйте ручку переноса. Подсвечивается цель, у краёв прокручиваются недели и строки; Escape или отпускание вне ячейки отменяют перенос. Также можно выбрать ячейку и нажать карточку облака, в том числе с клавиатуры. Замена заполненной ячейки требует подтверждения и отменяется через историю редактора. Каждую неделю можно просматривать и печатать отдельно.
- Обновления библиотеки применяются к конкретной практике вручную после просмотра изменений. Автоматическая массовая синхронизация не включена, чтобы правки каталога не изменяли готовые листы незаметно.
- Единый макет готового листа и скачиваемого серверного PDF; A4 в двух ориентациях и личные преднастройки «Чистый лист», «С названиями», «Для проведения». Браузерная печать остаётся отдельным действием. Есть переносимый JSON выбранного документа с нужными медиа и точными native source, предпросмотром импорта и новыми UUID.
- Личные категории практик, включая назначение одной практики нескольким папкам; вложенные занятия показывают контекст цикла.
- Скетчбук: свободные листы, цвет, лассо/рамка, преобразование нескольких штрихов и групп, автосохранение, копия, PNG и печать. Выделенную фигуру можно сделать карточкой или подготовить как независимый снимок для ячейки без засорения каталога.
- Объёмные фигуры людей по проверенной разметке своих рисунков: лицо, волосы, плечи, грудная клетка, талия, таз, суставы, кисти и стопы. Нейтральный персонаж, женщина и мужчина имеют разные пропорции объёмов тела. В наборе 23 октября поддержаны все 261 карточка, включая 75 архивных; в активной библиотеке — 186 из 186. Размеченные положения суставов и точки опоры сохраняются; глубина и невидимые части тела условны. Вариант хранится отдельным PNG 1024 × 1024 новой ревизии; исходники, прежние варианты и сохранённые практики не меняются. Линейный манекен сохраняет четыре прежних проверенных позы. Предпочтение влияет на будущие вставки; замена готового листа требует отдельного действия с предпросмотром и допускает undo. Подготовка полного набора описана в [контракте иллюстраций](app/Modules/Catalog/Illustrations/README.md).
- Режимы проведения и самостоятельной практики с параметрами времени, дыханий, сторон и повторов; личная история, схема покрытия зон и CSV. Это учёт выполнения в приложении, не измерение мышц.
- Медитация, дыхание и управляемые звуковые частоты: таймер с паузой/подготовкой, собственные синтезированные сигналы и фоны, личное MP3/M4A/WAV с прогрессом и Range, личная статистика. Файлы и история доступны только их владельцу внутри пространства.
- Дополнительно к доступу по логину — явная публикация неизменяемого снимка по случайной отзываемой ссылке/QR, со сроком и отдельным разрешением копирования. Исходники рисовалки и личное аудио публичная ссылка не открывает.
- Доступ другому зарегистрированному преподавателю по логину: просмотр либо просмотр и комментарии. Раздел «Мне дали доступ» открывает только выданные листы и их изображения; комментарии каждого приглашённого видны ему и владельцу, доступ можно отозвать.

Начальный каталог подготовлен из присланного владельцем листа; актуальная локальная база восстановлена из сохранённого снимка сайта. Нарезка и исходный манифест находятся в `resources/imports/reference-sheet/`. При регистрации создаются независимые копии активных карточек базового снимка.

История подготовки собственных рисунков и прежних импортов описана в `resources/imports/catalog-redraw/`, `resources/imports/spinal-arc-sheet/` и `resources/imports/server-catalog/`. Проверенная начальная разметка хранится в `resources/imports/catalog-taxonomy/`; условные рисунки и уровни требуют дальнейшего авторского уточнения. Текущие количества и результаты сохранности фиксируются в [docs/VERIFICATION.md](docs/VERIFICATION.md), не определяются seed-командами.

## Редактирование и обмен изображениями

В библиотеке нет отдельной кнопки обмена заданиями. Редактор картинки позволяет выгрузить JSON одного изображения через раздел «Экспорт изображения в JSON». Рисовалка сохраняет собственный исходник `ribka-drawing` с элементами и открывает его для дальнейшего редактирования без нейросети.

Пакетный обмен доступен через CLI. Задание содержит названия, исходные изображения в base64, идентификаторы, версии и инструкцию по обработке. Без указания карточек экспортируются первые 100 активных записей; общий размер изображений ограничен 32 МБ. Формат результата `ribka-codex-results-v1` сохранён для совместимости с прежними файлами:

```powershell
php artisan ribka:catalog-json export job.json --user=YOUR_LOGIN
php artisan ribka:catalog-json import results.json --user=YOUR_LOGIN
```

Результат должен содержать `workspace_id` исходного задания и `items` с `id`, `expected_revision` и `image_data` (`data:image/png;base64,...`). Для CLI вместо `image_data` допустим `image_file` с относительным путём внутри папки JSON. Импорт не перезаписывает карточку, изменённую после выгрузки, и сохраняет прежние изображения готовых практик. Встроенная генерация нейросетью требует отдельного провайдера/API; геометрическое сглаживание рисовалки работает локально без него.

Для новой установки доступен отдельный импорт через `ribka:import-asanas`; повторный запуск пропускает ранее импортированные карточки и сохраняет пользовательские правки. Скрипт запуска приложения не выполняет импорт автоматически. Формат и команды описаны в [docs/IMPORT_ASANAS.md](docs/IMPORT_ASANAS.md). Собственные изображения также можно загрузить через интерфейс.

## Локальный запуск в Windows

Нужны Docker Desktop с запущенным Linux engine, Docker Compose v2 с поддержкой `--wait` и PowerShell. PHP, Composer, Node.js и PostgreSQL на Windows устанавливать не требуется. Docker Desktop должен иметь доступ к каталогу проекта. При первом запуске понадобится доступ к реестрам образов, Composer и npm.

Из каталога проекта:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\start.ps1
```

Скрипт создаёт `.env` из `.env.example` **только при его отсутствии**, генерирует случайные `APP_KEY` и пароль БД, собирает PHP-образ, запускает PostgreSQL, устанавливает зависимости из lock-файлов, применяет новые миграции, собирает frontend и запускает приложение. Затем проверяет `/up` и `/login`.

Адрес по умолчанию: **http://localhost:8080**. Веб-порт привязан только к `127.0.0.1`. Для другого порта измените `APP_PORT` и `APP_URL` в `.env`, затем повторите запуск.

Существующий `.env` и база не перезаписываются. Скрипт останавливается при ошибке; частично выполненный запуск не требует сброса данных — исправьте причину и запустите снова. Пользователи автоматически не создаются. Если для текущей локальной установки подготовлен `.runtime/local-access.txt`, учётные данные находятся в этом локальном файле; он исключён из Git. Не публикуйте его.

Остановка с сохранением базы, файлов и зависимостей:

```powershell
.\scripts\stop.ps1
```

Повторный быстрый запуск уже установленной версии:

```powershell
docker compose up -d --wait app web
```

После изменений зависимостей, миграций или frontend запускайте полный `scripts/start.ps1`.

## Linux, macOS и WSL

Нужны Docker Engine/Desktop, Compose v2 и `openssl` для первоначальной генерации секретов:

```sh
sh scripts/start.sh
```

Этот скрипт выполняет те же шаги, сохраняет существующий `.env` и проверяет HTTP-ответ приложения. Остановка:

```sh
docker compose stop
```

Исходники смонтированы в контейнеры. PostgreSQL, `vendor` и `node_modules` находятся в именованных Docker volumes. Приватные изображения сохраняются в `storage/app/private` в каталоге проекта. Команда `docker compose down` сохраняет volumes, но для повседневной остановки достаточно `stop`. **Не используйте `down -v`, `migrate:fresh`, `db:wipe` или ручное удаление storage для обновления приложения.**

## Аккаунты, профиль и доступ

Откройте `/register`, укажите имя, логин, email и пароль не короче 8 символов. Новый пользователь получает отдельное пространство и независимые копии карточек базовой библиотеки из локального снимка. Чужие практики и подборки в этот кабинет не переносятся. По умолчанию предоставляется 14 дней тарифа «Про» без оплаты; срок задаётся `RIBKA_TRIAL_DAYS`. После окончания действует базовый тариф. Для копирования базовой библиотеки должны присутствовать `database/seeders/snapshot/dataset.json.gz` и файлы снимка.

Вход выполняется по логину и паролю. Логин уникален, не зависит от регистра и содержит латинские буквы, цифры, точки, дефисы или подчёркивания (первый символ — буква или цифра, максимум 64 символа). Email используется для восстановления доступа. При обновлении существующим аккаунтам назначаются логины из имени в латинице; при совпадениях добавляется числовой суффикс.

В `/account` можно изменить имя, контакты, реквизиты, название своего пространства и аватар; аватар хранится приватно. Для смены логина или почты нужен текущий пароль. Здесь же доступны смена пароля, состояние подписки, лимиты и история фактических платежей.

Восстановление пароля: `/forgot-password` → email → ссылка → новый пароль. При локальном `MAIL_MAILER=log` письмо записывается в `storage/logs/local-mail.log`; SMTP не требуется. Ссылка использует `APP_URL`, поэтому он должен совпадать с адресом локального приложения. На production с `MAIL_MAILER=log` форма честно сообщает, что отправка не подключена. Для реальной доставки нужны SMTP host/port, схема, отправитель и реквизиты в серверном `.env`, затем `php artisan config:cache` и фактическая проверка письма. Telegram/SMS-восстановление требует отдельного провайдера и пока не реализовано.

Оператор по-прежнему может создать пустое пространство и добавить преподавателя командами Artisan. Пароль вводится скрыто, дважды, минимум 12 символов:

Выполняйте команды после запуска приложения. Пароль вводится скрыто, дважды, минимум 12 символов. В командную строку пароль передавать не нужно.

```sh
php artisan ribka:workspace "Моя практика" --email=author@example.com --user="Автор" --login=author
```

Команда напечатает UUID нового рабочего пространства. Используйте его для отдельного аккаунта преподавателя:

```sh
php artisan ribka:member WORKSPACE_UUID --email=teacher@example.com --user="Преподаватель" --login=teacher --role=editor
```

Участники одного пространства работают с общей библиотекой и документами. Регистрирующиеся преподаватели получают разные пространства. Один пользователь принадлежит одному пространству; роли: `owner` и `editor`. Дополнительное членство по-прежнему назначает оператор.

Административный сброс пароля без почтового сервиса:

```sh
php artisan ribka:password teacher@example.com
```

Активные сеансы этого аккаунта и старые remember-токены сбрасываются. Для контролируемого первоначального развёртывания команды также поддерживают окружение `RIBKA_INITIAL_PASSWORD`; не записывайте его в репозиторий, `.env.example`, shell history или общедоступные журналы. Обычный интерактивный ввод предпочтительнее.

## Подписки и администрирование

Тарифы и лимиты находятся в `config/billing.php`: базовый — до 30 активных асан и 5 практик/шаблонов, «Про» — без этих лимитов и с мезоциклами. Необязательные настройки окружения: `RIBKA_BASIC_ASANAS`, `RIBKA_BASIC_PRACTICES`, `RIBKA_TRIAL_DAYS`. Истечение пробного или выданного периода возвращает базовые ограничения; ранее созданные документы сохраняются. Существующие пространства из прежней установки получают бессрочный ручной «Про», чтобы обновление не ограничило их работу.

Администратор назначается явно:

```sh
php artisan ribka:admin author
# Снять права:
php artisan ribka:admin author --revoke
```

В `/admin` доступны поиск пользователей, состояние их доступа, ручная выдача выбранного тарифа на срок или бессрочно и JSON-отчёт. Доступ меняется для всего пространства пользователя. Выдача записывается в журнал, проверяет версию подписки и не создаёт фиктивный платёж. Обычные пользователи не могут открыть административные API.

Оплата, привязка карт и автосписания ещё не подключены. Кабинет показывает это явно. Финансовая сводка учитывает только подтверждённые платежи из `billing_payments`, а ручные выдачи доступа не считаются выручкой. Для коммерческого запуска нужен выбранный эквайринг, его ключи и проверяемые уведомления об оплате; после подключения именно подтверждённые уведомления должны продлевать подписки. Конкретных цен в приложении пока нет.

Контракт модуля Billing — `Entitlements::lock()`, `limits()`, `assertCanCreate()` и `SubscriptionAccess`. При создании ограничиваемого объекта блокировка подписки и подсчёт текущего количества выполняются в одной транзакции. Архивные данные не удаляются при достижении лимита.

| Модуль        | Ответственность                                              | Публичный контракт                                                                               |
| ------------- | ------------------------------------------------------------ | ------------------------------------------------------------------------------------------------ |
| `Access`      | Аккаунты, пространства и членство                            | `WorkspaceContext::id()`, `userId()`, `details()`                                                |
| `Billing`     | Тарифы, пробные периоды, ручные выдачи и фактические платежи | `Entitlements`, `SubscriptionAccess`                                                             |
| `Media`       | Проверка, приватное хранение и выдача файлов                 | `AssetStore::store()`, `get()`, `getMany()`, `discardUnattached()`                               |
| `Catalog`     | Асаны, алиасы, плоские категории, поиск и архив              | `AsanaReader::findMany()`                                                                        |
| `Collections` | Подборки и порядок карточек                                  | Авторизованные HTTP-маршруты `/api/collections`                                                  |
| `Practices`   | Документы, снимки карточек, блоки, строки, ячейки, шаблоны   | Авторизованные HTTP-маршруты `/api/practices`, `/api/row-templates`, `/api/editor/cards/resolve` |

Бизнес-код находится в `app/Modules`, frontend — в `resources/js/modules`, общие компоненты — в `resources/js/shared`. Модуль владеет своими моделями и таблицами. Межмодульные операции выполняются через контейнер Laravel и публичные контракты, без HTTP-запросов приложения к самому себе и без импорта чужих Eloquent-моделей.

Пространство определяется из авторизованного пользователя на сервере. Каталог, подборки, документы, снимки и изображения проверяются на принадлежность пространству. Сохранение использует ожидаемую версию; при конфликте сервер возвращает 409. Изображения неизменяемы: замена создаёт новый asset, архивирование асаны не удаляет изображения старых листов.

## Настройки и изображения

Для явного административного импорта подготовленных локальных карточек есть команда `ribka:import-asanas`. Формат манифеста, проверка владельца и повторный запуск без изменения ранее импортированных карточек описаны в [docs/IMPORT_ASANAS.md](docs/IMPORT_ASANAS.md).

Основные значения находятся в `.env.example`; реальные секреты хранятся только в `.env`. Для текущего локального HTTP-запуска `SESSION_SECURE_COOKIE=false`. При отдельном HTTPS-развёртывании настройте домен, cookies, закрытый storage, резервные копии и секреты под своё окружение.

Поддерживаются **PNG, JPEG, WebP**, до **10 МБ** и **25 мегапикселей** на файл, до 30 файлов за действие в интерфейсе. Каждый файл загружается отдельно; ошибка одного файла не отменяет остальные. SVG, GIF, PDF, ZIP и загрузка произвольного URL не поддерживаются.

- Лимиты приложения: `config/ribka.php`, необязательные `RIBKA_UPLOAD_MAX_KB` и `RIBKA_UPLOAD_MAX_PIXELS` в `.env`.
- PHP: `upload_max_filesize=12M`, `post_max_size=16M`, `memory_limit=512M` в `docker/php/php.ini`.
- Nginx: `client_max_body_size 16m` в `docker/nginx/default.conf`.
- Файлы: `storage/app/private/media`; произвольные имена пользователя не используются как серверные пути.
- Оригиналы и миниатюры доступны через авторизованный `/media/{id}`, с запретом публичного кеширования. `php artisan storage:link` для этих изображений не требуется.

При изменении лимитов согласуйте приложение, интерфейс, PHP и Nginx, затем пересоберите PHP-образ и перезапустите контейнеры. Не меняйте `DB_PASSWORD` у уже инициализированного PostgreSQL volume без отдельного изменения пароля внутри БД: переменная контейнера применяется при первоначальной инициализации.

## Резервные копии

Полная копия состоит из **PostgreSQL + всего `storage/app/private` + защищённой копии `.env` с APP_KEY**. Одна база без файлов не восстановит изображения. Для согласованной копии прекратите работу пользователей и остановите веб-контейнер на время выгрузки. Храните копии вне проекта и переносите их в защищённое хранилище.

Пример ручной копии в PowerShell, без передачи пароля в аргументах и без перенаправления бинарных данных через старый PowerShell:

```powershell
$backupDirectory = Join-Path (Split-Path -Parent (Get-Location).Path) ('RibkaYoga-backup-' + (Get-Date -Format 'yyyyMMdd-HHmmss'))
New-Item -ItemType Directory -Path $backupDirectory | Out-Null
docker compose stop web
try {
    docker compose exec -T db sh -c 'pg_dump -U "$POSTGRES_USER" -d "$POSTGRES_DB" -Fc -f /tmp/ribka-backup.dump'
    if ($LASTEXITCODE -ne 0) { throw 'Не удалось выгрузить PostgreSQL.' }
    docker compose cp db:/tmp/ribka-backup.dump (Join-Path $backupDirectory 'database.dump')
    if ($LASTEXITCODE -ne 0) { throw 'Не удалось скопировать дамп.' }
    Copy-Item -LiteralPath '.\storage\app\private' -Destination (Join-Path $backupDirectory 'private') -Recurse
    Copy-Item -LiteralPath '.\.env' -Destination (Join-Path $backupDirectory '.env')
} finally {
    docker compose start web
}
```

В Linux/macOS выполните те же операции: остановите `web`, создайте `pg_dump -Fc` внутри `db`, скопируйте дамп через `docker compose cp`, затем скопируйте приватный storage и `.env` и верните `web` в работу. Контейнер БД продолжает работать.

Восстановление проверяйте сначала в отдельном экземпляре: создайте пустую БД с подходящими настройками, восстановите дамп через `pg_restore`, верните приватные файлы и исходный `APP_KEY`, обеспечьте PHP доступ на запись к storage и запустите приложение. В существующую рабочую БД дамп поверх данных не импортируйте. Схему, пути и секреты копии нужно восстанавливать согласованно.

# Пять оригинальных листов «Дуга позвоночника»

Новый набор владельца от 2 ноября 2026 года: `1_1.jpg`–`1_5.jpg`. Фигуры вырезаны из оригиналов без перерисовки и генерации. Все 399 вхождений сохранены отдельными PNG 512 × 512 с белыми полями и прежними пропорциями. Увеличение не добавляет деталей исходным миниатюрам; собственные зелёные движения и реквизит остаются в рисунках. Соседние номера, скобки, S, звёзды и знаки переходов отделены от фигур.

- `sheet-1`–`sheet-5`: оригинал, координаты, исключённые прямоугольники пометок, отдельные PNG и контактлисты. Все 11 контактлистов просмотрены, спорные изображения дополнительно сверены между двумя редакторами.
- `dedup.json`: итог ручной визуальной сверки — 153 группы из 399 вхождений. Для каждой группы сохранены выбранный оригинал, все исходные ключи и причина объединения. `dedup-a.json`, `dedup-b.json` и `dedup-cross-b.json` содержат исходные решения двух редакторов и девять подтверждённых объединений между частями. Одинаковые позы с мелкими различиями почерка объединены; разные опоры и существенные положения тела сохранены. Совпадение имени само по себе не является основанием объединения.
- `prepare.py`: собирает карточки и собственную вводную справку, затем применяет `dedup.json`. Коды листа/строки/позиции остаются в происхождении, не в пользовательском названии.
- `manifest.json`: **153 карточки** для `ribka:import-asanas`; описание, подсказки, польза, предосторожности и частичные признаки. У 105 описательных вариантов стоит «уточнить». `editorial.reviewed=false` у всех; сложность не выводится из рисунка. Альтернативные и санскритские названия заполнены только там, где есть достаточно определённое соответствие.
- `occurrences.json`: связь всех 399 исходных вхождений с постоянными ключами 153 канонических карточек.
- `practices.py`: по UUID импортированных асан подготавливает пять манифестов практик. Читает SQLite без изменения данных. Каждая ячейка с картинкой содержит `source_image` — относительный путь к своему исходному PNG: объединение каталога не заменяет рисунок на готовом листе. `practice-provenance.json` связывает строки приложения со строками оригиналов.
- `practice-1.json`–`practice-5.json`: 412 ячеек — 399 изображений и 13 текстовых обозначений. Сохранены 72 группы, 18 отметок S, 2 звезды и 345 межклеточных знаков. Строка 1.2 пятого листа разложена как в исходных двух визуальных линиях: 8 + 6 ячеек, без разделения скобок. Из-за лимита 12 ячеек это две строки приложения; исходная нумерация указана в заметках. Нижние расшифровки СВ листов 2 и 3 — отдельные блоки «СВ», не дополнительные основные упражнения. Буквы СВ и «10 Т.Ш.» не расшифровывались предположительно.
- `starter.py`: экспортирует 153 карточки и выбранные канонические оригиналы в `starter/` для новых аккаунтов; проверяет соответствие текущему манифесту. Набор не содержит аккаунтов, паролей, практик или прежних данных. Старый приватный snapshot не используется `StarterLibrary`.

Справка описывает форму и задачу движения, не обещает лечебных эффектов и не задаёт дозировку или дыхание по миниатюре. Неочевидные варианты требуют проверки преподавателем. Общий подход к осторожности для сложных и перевёрнутых положений согласуется с [NCCIH — Yoga: Effectiveness and Safety](https://www.nccih.nih.gov/health/yoga-effectiveness-and-safety).

Порядок повторного импорта в **явно выбранную подготовленную локальную базу**, без её очистки:

1. `python3 resources/imports/spinal-five-20261102/prepare.py`
2. `php artisan ribka:import-asanas resources/imports/spinal-five-20261102/manifest.json --workspace=UUID --owner=EMAIL --dry-run`, затем та же команда без `--dry-run`.
3. `python3 resources/imports/spinal-five-20261102/practices.py /absolute/path/to/database.sqlite`
4. Каждый `practice-N.json` проверить и импортировать через `ribka:import-practice-sheet` с `--workspace`, `--owner` и постоянным `--result` вне Git. Журнал dry-run и журнал настоящего импорта должны быть разными файлами.
5. `python3 resources/imports/spinal-five-20261102/starter.py /absolute/path/to/database.sqlite` — только после проверки состава каталога.

Команды не очищают базу. Повторный импорт карточек пропускает существующие ключи; импорт практик с прежним журналом не создаёт дубликаты. Изменение названия в манифесте не перезаписывает пользовательские правки.

`ribka:import-practice-sheet` допускает `source_image` только вместе с `asana_id`. Путь должен вести к читаемому локальному изображению внутри папки манифеста: URL, абсолютные пути, `..` и символьные ссылки запрещены. Хеш содержимого включается в отпечаток журнала, точные байты закрепляются через модуль Media. Файл не заменяет изображение асаны в каталоге. Манифесты без `source_image` сохраняют прежнее поведение и прежний отпечаток.

После отдельного поручения убрать повторы в основной локальной базе объединены 246 карточек. Резервные базы и журнал — `.runtime/catalog-dedup-20261102/`. Ссылки снимков переведены на канонические карточки, но имена и изображения всех 399 снимков, структура пяти практик, группы и обозначения не изменены. Повторный импорт обновлённых манифестов не предназначен для объединения уже существовавшего каталога: это была отдельная операторская операция с резервированием.

По прямому поручению владельца прежнее содержимое локальной базы было удалено отдельной операторской операцией после резервирования. Резервная база, полный архив приватных файлов и журналы находятся в `.runtime/catalog-reset-20261102/`, не в Git. Учётная запись, пространство, тариф и настройки медитации сохранены. На удалённом сервере изменений не выполнялось.

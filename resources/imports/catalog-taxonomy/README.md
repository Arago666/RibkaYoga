# Проверенная первичная разметка — 22 октября 2026

`verified-20261022.json` — аддитивная разметка по **точным текущим изображениям** 184 действующих карточек. Перед подготовкой визуально просмотрены все 186 изображений в семи контактных листах. Две авторские технические карточки проверки рисовалки оставлены без классификации. Изображения, названия и прежние пользовательские категории не заменяются.

Манифест привязан к UUID пространства, UUID карточки, её ревизии и UUID неизменяемого изображения. При несовпадении любой указанной предпосылки команда прекращает всю транзакцию. `manual_verified` означает отдельную визуальную сверку конкретного рисунка при подготовке этого списка; это **не** утверждение о полной методической проверке техники или сложности. Объяснение сохранено в `review_note` каждого элемента.

Все записи имеют `classification_status: partial`. Назначено:

- положение — 181 карточке;
- однозначное направление/эффект — 152 карточкам;
- ограниченные ориентиры корпуса или опоры — 56 карточкам;
- сложность — ни одной: по условной фигурке уровень не угадывается.

У 60 авторских или неоднозначных вариантов отдельно отмечена необходимость уточнения техники. Неуказанные группы означают отсутствие подтверждённых данных. В частности, условные горизонтальные позы не разделены на положение на животе/спине без достаточной опоры. Не выводятся «детокс», терапевтическая польза, пригодность каждому, точные мышцы и проценты нагрузки.

Словарь создаётся отдельно:

```sh
php artisan ribka:seed-taxonomy --apply
```

Предпросмотр без записи — режим по умолчанию:

```sh
php artisan ribka:classify-asanas resources/imports/catalog-taxonomy/verified-20261022.json --workspace=UUID --owner=EMAIL
```

После просмотра результата тот же вызов с `--apply` атомарно применяет разметку. Повтор со старыми ревизиями не перезаписывает более свежие изменения: для нового применения нужен новый проверенный экспорт. В интерфейсе очередь «Не размечены» намеренно продолжает показывать частичные карточки: владельцу ещё предстоит подтвердить отсутствующие методические данные, прежде всего уровень сложности.

Первичное применение проверено на отдельной базе разработки `.runtime/implementation-20261022/development.sqlite`, не на сервере: 184 ревизии увеличены ровно на один; 261 карточка, все изображения/исходники, архивные флаги, алиасы, прежние назначения категорий, снимки и содержимое ячеек сохранены. SQL-проверка внешних ключей не выявила нарушений. Отчёты и контакты находятся в закрытой `.runtime`; автоматические тесты не создавались.

`starter-provenance-20261022.json` позволяет перенести эту проверенную разметку
в новый каталог из прежнего приватного стартового набора. Он фиксирует SHA-256
самого манифеста, точного PNG и нормализованного серверным валидатором native JSON
для каждой пары исходных UUID карточки/asset. `StarterClassification` дополнительно
проверяет исходное пространство и `manual_verified`. При любом несовпадении
добавочная разметка не применяется. Значения сопоставляются по системным ключам
с новыми UUID категорий, ссылки на исходное пространство не копируются.

Свежий приватный стартовый набор уже может содержать признаки и их назначения;
сам набор с PNG располагается вне Git в `database/seeders/snapshot`. Резервный
механизм не подменяет его файлы. Регистрация проверена на отдельной SQLite и
изолированном хранилище: 184 новые карточки/изображения/native, те же 181/152/56
назначений и ни одного угаданного уровня. Повторное заполнение не создало копий.
Прямое отношение между двумя карточками отдельного небольшого приватного набора
правильно перенесено вторым проходом на новые UUID. Чужие ссылки и нарушения
внешних ключей отсутствуют; исходные карточки остались неизменны.

## Собственная визуальная справка

`reference-content-20261022.json` содержит 184 описания конкретных рисунков и
34 краткие последовательности пространственных действий для однозначных схем.
Соответствие снова проверено по семи контактным листам текущих PNG, а не по
совпадению названия. Тексты написаны для RibkaYoga; материалы конкурентов не
копировались. Две технические карточки исключены.

Это начальная визуальная справка: `editorial.reviewed=false` у всех карточек,
70 вариантов отдельно требуют уточнения названия, опор или техники. Полная
методика входа и выхода, дыхание, дозировка, противопоказания и адаптации не
выводятся из условного рисунка. Неизвестные поля и сложность остаются пустыми.
Короткие описания доступны в подсказках преподавателю, происхождение и
ограничения — в редакционной части карточки; историческая скрытая заметка не
изменяется.

Манифест применяется отдельной командой `ribka:enrich-references`, по умолчанию
только предпросмотр. Запись требует `--apply`, владельца и точное пространство,
проверяет ревизию и неизменяемое изображение каждой карточки. Заполненные
автором шаги или подсказки не перезаписываются. Повтор уже внесённых точных
данных не повышает ревизию. Имена, рисунки, native, категории и прежние снимки
этот перенос не изменяет.

Разметка и справка после проверок копий SQLite/PostgreSQL внесены также на
действующий сервер 22 октября. Полные результаты сохранности и пути двух
свежих резервных копий записаны в `docs/VERIFICATION.md`. Старые снимки практик
не переклассифицированы, архивные карточки не восстановлены.

# Импорт подготовленных карточек

Команда `ribka:import-asanas` предназначена для явного административного импорта локальных изображений. Она не скачивает URL, не распознаёт названия поз и не меняет сохранённые практики или снимки карточек. Картинки заранее подготавливаются отдельно; в случае вырезок из фотографии листа названия могут быть описательными и требовать уточнения преподавателем.

В поставку включён манифест `resources/imports/reference-sheet/manifest.json` с **71 карточкой** из исходного листа пользователя. Он уже импортирован в текущее локальное рабочее пространство. **34 названия** помечены «уточнить» и предназначены для проверки преподавателем. Новая установка может загрузить тот же набор командой ниже; повторный запуск в том же пространстве не меняет уже импортированные карточки.

Перед первым импортом примените миграции, включая `2026_09_28_000007_add_catalog_import_keys.php`, которая добавляет ключи импорта:

```sh
docker compose exec app php artisan migrate --force
```

Манифест в UTF-8 — объект `source` и `items`:

```json
{
  "source": "Базовая последовательность — исходный лист пользователя",
  "items": [
    {
      "source_key": "reference-sheet:row-1.1:cell-1",
      "name": "Поза из строки 1.1, карточка 1",
      "description": "Название требует уточнения по оригиналу.",
      "aliases": ["Строка 1.1"],
      "image": "assets/001.png"
    }
  ]
}
```

Для подготовленного листа путь: `resources/imports/reference-sheet/manifest.json`, изображения — в подкаталоге `assets`. Путь `image` считается относительно каталога манифеста. Абсолютные пути, URL и выход из каталога, в том числе через символические ссылки, запрещены. Манифест ограничен 1 МБ и 500 карточками. Название — до 160 символов, описание — до 4000, источник — до 255, ключ — до 190. Изображения проходят ту же проверку Media, что обычные загрузки: PNG/JPEG/WebP, фактический MIME, декодирование GD, размер и число пикселей.

Проверка структуры манифеста и доступности новых файлов без записи:

```sh
docker compose exec app php artisan ribka:import-asanas resources/imports/reference-sheet/manifest.json --workspace=WORKSPACE_UUID --owner=author@example.com --dry-run
```

В `--workspace` и `--owner` укажите реальные UUID пространства и email его владельца. Команда проверяет их связь через публичный контекст Access. Аккаунт не создаётся, пароль не требуется: командой пользуется оператор с доступом к серверу. `--dry-run` не создаёт файлы или записи; полная проверка декодирования выполняется при настоящем импорте.

Импорт:

```sh
docker compose exec app php artisan ribka:import-asanas resources/imports/reference-sheet/manifest.json --workspace=WORKSPACE_UUID --owner=author@example.com
```

`source_key` — постоянный ключ исходной карточки, уникальный внутри рабочего пространства. Не меняйте его при исправлении описания манифеста. Повторный запуск пропускает уже импортированные карточки **вместе с архивными**: он не заменяет их изображения, не сбрасывает категории, теги, названия, описания и пользовательские правки. Новые ключи создают новые карточки. Источник хранится отдельно в каталоге и добавляется к начальному описанию.

Каждая карточка сохраняется отдельной транзакцией. Ошибка одной не удаляет ранее добавленные; команда сообщает количество добавленных, пропущенных и ошибок, возвращая ненулевой код при ошибках. После исправления проблем повторите ту же команду. Уникальное ограничение БД защищает от дублей при одновременном запуске.

Файлы копируются через Media в приватный `storage/app/private/media`, исходные подготовленные файлы остаются на месте. Каталог `resources/imports` не является публичной веб-директорией. Не переносите приватные исходники в `public` и не настраивайте для них открытый файловый маршрут.

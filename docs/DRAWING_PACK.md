# Импорт редактируемых рисунков

Локальная команда `ribka:import-drawing-pack` принимает PNG 1024 × 1024 вместе с исходниками редактора `ribka-drawing`. Она обновляет изображения существующих карточек без изменения их названий, категорий, альтернативных названий, заметок и принадлежности подборкам. Новые карточки получают категории и добавляются в указанную активную подборку через публичный контракт Collections.

До применения пакета нужно сохранить резервную копию локальной БД и `storage/app/private`. Старые файлы Media и ранее созданные снимки практик команда не удаляет и не изменяет. Для нового листа практика создаётся отдельно обычным API Practices: сначала разрешаются карточки в независимые снимки, затем сохраняется структура листа. Исходники рисунков в снимки не включаются.

## Формат пакета

Манифест и все его файлы находятся в одной папке. Пути относительные, после раскрытия символических ссылок они должны оставаться внутри папки манифеста. Один пакет содержит до 500 элементов; сумма PNG и исходников — до 128 МБ. Максимальный размер одного исходника — 4 МБ, одного PNG — действующий лимит загрузки Media.

```json
{
  "format": "ribka-drawing-pack-v1",
  "workspace_id": "UUID пространства",
  "source": "2 Х/Б — Дуга позвоночника. Носки",
  "collection_id": "UUID заранее созданной активной подборки",
  "items": [
    {
      "key": "catalog:UUID карточки",
      "id": "UUID существующей карточки",
      "expected_revision": 3,
      "image_file": "images/existing.png",
      "source_file": "sources/existing.json"
    },
    {
      "key": "sheet:1.1:1",
      "import_key": "spine-arc-toes-20261014:1.1:1",
      "name": "Положение с листа — 1.1.1 (уточнить)",
      "aliases": ["2 Х/Б — Дуга позвоночника. Носки", "1.1.1"],
      "category_ids": ["UUID категории этого пространства"],
      "image_file": "images/sheet-1-1-1.png",
      "source_file": "sources/sheet-1-1-1.json"
    }
  ]
}
```

Для обновления обязательны `id` и `expected_revision`; метаданные создавать или заменять в этом элементе нельзя. Для новой карточки обязательны `import_key`, непустое `name`, `category_ids` и `collection_id` пакета. `key` — уникальная строка только для сопоставления результатов; `import_key` — постоянный уникальный ключ новой карточки внутри пространства. Название источника записывается в `import_source` новых карточек. Если название отдельной позы отсутствует на листе или неоднозначно, нельзя выдавать предположение за прочитанное название: оно отмечается «уточнить».

Каждый `source_file` — точный формат редактора:

```json
{
  "format": "ribka-drawing",
  "version": 1,
  "width": 1024,
  "height": 1024,
  "smoothing": 0,
  "elements": [
    {
      "id": "UUID элемента",
      "kind": "line",
      "width": 8,
      "rotation": 0,
      "points": [{"x": 400, "y": 400}, {"x": 550, "y": 650}]
    }
  ]
}
```

Серверный `DrawingSource` проверяет полный набор ключей, допустимые типы элементов, UUID, точки и пределы сложности. Команда проверяет MIME, размер PNG и декодирование PHP GD. PNG следует экспортировать тем же рендерером редактора из приложенного исходника; команда проверяет форматы, но не сравнивает геометрию PNG и исходника.

## Применение

Команда доступна только от имени владельца указанного пространства. Она не создаёт сессию, не меняет аккаунт и восстанавливает прежнюю идентификацию после выполнения. Вместо примеров UUID и email указываются реальные значения локального проекта.

```sh
php artisan ribka:import-drawing-pack .runtime/drawing-pack/manifest.json \
  --workspace=UUID --owner=owner@example.test --dry-run \
  --result=.runtime/drawing-pack/preflight.json

php artisan ribka:import-drawing-pack .runtime/drawing-pack/manifest.json \
  --workspace=UUID --owner=owner@example.test \
  --result=.runtime/drawing-pack/import-result.json
```

`--dry-run` не меняет карточки, БД и файлы Media; если передан `--result`, он создаёт только отчёт в указанной папке. Проверяются все исходники, PNG, владение карточками и категориями, ожидаемые ревизии, ключи повторного импорта и действующий лимит каталога. Доступность и вместимость активной подборки окончательно проверяются контрактом Collections в транзакции сохранения. Ошибка доступа, размера подборки или любого другого элемента откатывает весь пакет.

Запись выполняется в одной транзакции с обычным порядком блокировок: пространство Collections, лимит каталога, карточки по UUID, категории. Каждая замена создаёт новый неизменяемый Asset и одновременно сохраняет исходник с увеличением ревизии. При ошибке удаляются только новые незакреплённые Asset этой операции; ранее существовавшие файлы не затрагиваются. Лимит подписки не обходится.

Повторение идентичного пакета возвращает `unchanged` и не увеличивает ревизии. Обновление при несовпадающей `expected_revision` допускает только этот точный уже сохранённый PNG и исходник; любое другое содержимое отклоняется. Занятый `import_key` новой карточки допускается только для того же `import_source`, исходника и PNG. Позднее изменённые пользователем метаданные не перезаписываются. Ключ с другим рисунком вызывает ошибку.

`--result` требует нового файла и не перезаписывает существующий отчёт. Ответ `ribka-drawing-pack-result-v1` содержит `items[{key,id,revision,status}]`; возможны `update`, `create`, `unchanged`, а при проверке — `would_update` и `would_create`. UUID новых карточек появляются только после сохранения. При ошибке записи отчёта после успешной транзакции данные уже сохранены; повтор команды с другим новым именем отчёта восстановит сопоставление безопасно.

Автоматические тесты для этого сценария не создаются и не запускаются. Проверки: PHP lint, Laravel Pint для изменённых PHP-файлов, доступность команды через Artisan, проверка реального пакета `--dry-run`, просмотр рисунков и ручное повторное открытие карточек в редакторе.

## Создание практики по листу

После импорта карточек команда `ribka:import-practice-sheet` создаёт практику с независимыми снимками и заданной структурой. Манифест использует UUID карточек из результата импорта рисунков:

```json
{
  "format": "ribka-practice-sheet-v1",
  "title": "2 Х/Б — Дуга позвоночника. Носки",
  "theme": "Дуга позвоночника. Носки",
  "blocks": [
    {
      "id": "уникальный UUID блока",
      "title": "1",
      "rows": [
        {
          "id": "уникальный UUID строки",
          "note": "1.1",
          "cells": [
            {"id": "уникальный UUID ячейки", "asana_id": "UUID карточки", "group_key": "UUID группы"},
            {"id": "другой уникальный UUID ячейки", "asana_id": "UUID другой карточки", "group_key": "UUID той же группы"}
          ]
        }
      ]
    }
  ]
}
```

`workspace_id` в манифесте необязателен; при наличии обязан совпадать с `--workspace`. Допустимы `purpose` блока, `note` строки и ячейки, `group_key` и `arrow_direction`. Для пустой ячейки указывается `asana_id: null`; у такой ячейки не может быть подписи. Текстовая ячейка содержит `asana_id: null` и `custom_name`; одновременно название и карточка запрещены. Группа содержит минимум две соседние ячейки одной строки. Используются те же ограничения дерева, что у `DocumentRequest`, включая общий предел ячеек. UUID всех блоков, строк и ячеек входного манифеста уникальны; `copyLocal` создаёт для новой практики собственные UUID структуры.

```sh
php artisan ribka:import-practice-sheet .runtime/drawing-pack/practice-sheet.json \
  --workspace=UUID --owner=owner@example.test --dry-run \
  --result=.runtime/drawing-pack/practice-preflight.json

php artisan ribka:import-practice-sheet .runtime/drawing-pack/practice-sheet.json \
  --workspace=UUID --owner=owner@example.test \
  --result=.runtime/drawing-pack/practice-result.json
```

`--result` обязателен и служит постоянным журналом идемпотентности. Команда эксклюзивно создаёт новый файл и держит его блокировку до завершения; при уже занятом файле завершится без повторной практики. Существующий успешный журнал используется только при совпадении пространства, названия и отпечатка нормализованного манифеста, а UUID документа проверяется через `PracticeEditor`. Такой повтор не создаёт снимков, не меняет ревизии и не перезаписывает журнал. Отчёт `dry-run` имеет `document: null`; для сохранения нужен другой новый файл. Совпадение названия с другой практикой в БД не считается доказательством предыдущего импорта.

Проверка `--dry-run` читает доступные активные карточки через `AsanaReader`, проверяет структуру и лимит практик, но не вызывает `resolveCards` и не создаёт снимки. Реальный запуск в общей транзакции создаёт снимки через `PracticeEditor::resolveCards` порциями до 100 асан и сохраняет документ через `copyLocal`. Результат `ribka-practice-sheet-result-v1` содержит `document{id,title,revision}`, количество карточек и ячеек. Журнал записывается и сбрасывается на диск до завершения транзакции; ошибка записи откатывает практику и снимки и удаляет только свежий журнал этой операции. После аварийного завершения с повреждённым или пустым журналом требуется проверить предыдущий импорт и выбрать новый файл; по одному совпадению названия команда не решает, что документ уже создан.

# Модули и серверные контракты

Приложение — один Laravel-проект с одной PostgreSQL-базой и единым запуском. Модули вызывают друг друга в процессе PHP через контейнер Laravel; внутренний HTTP и отдельные сервисы не используются. Провайдеры подключены в `bootstrap/providers.php`, миграции проходят общим упорядоченным потоком.

## Границы

| Модуль      | Собственные данные и обязанности                                                                                           | Публичный контракт                                                                                                                   |
| ----------- | -------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| Access      | Пространства, участники `owner/editor`, служебные команды аккаунтов; Laravel/Fortify отвечает за сеансы                    | `WorkspaceContext::id()`, `userId()`, `details()` определяют доступ по авторизованному сеансу                                        |
| Media       | Приватные неизменяемые изображения/миниатюры, отдельные личные аудиофайлы                                                  | `AssetStore`, `AssetFingerprints`, `PublishedImages`, `AudioStore`                                                                   |
| Catalog     | Асаны, другие названия, личные категории, четыре группы системных признаков, отношения вариантов, личное избранное и поиск | `AsanaReader`, `StarterLibrary`, `CatalogUsage`, `PoseFacts`, `DrawingSources`, `IllustrationStyles`                                 |
| Collections | Тематические подборки, папки подборок и их состав                                                                          | `CollectionMembership` управляет составом в транзакции; ссылки на асаны проверяются через Catalog                                    |
| Practices   | Практики, шаблоны, фрагменты, строки/связки, циклы, личные папки документов, снимки, доступ и публикация                   | `ExecutionDocuments`, `DrawingSnapshots`, `NativeImages`, `DocumentMediaAccess`, `PublicationMediaAccess`, собственные JSON-маршруты |
| Sessions    | Личная история выполнения практик, снимок плана и продвижение                                                              | Читает разрешённый план только через `Practices\PublicApi\ExecutionDocuments`                                                        |
| Sketchbook  | Личные листы свободного рисования и владение их изображениями                                                              | `SketchImages` проверяет владельца; перенос фигуры вызывает `Practices\PublicApi\DrawingSnapshots`                                   |
| Meditation  | Личные настройки, управляемые сессии медитации и история                                                                   | Аудио только через `Media\PublicApi\AudioStore`; внутренний контракт описан в `app/Modules/Meditation/README.md`                     |
| Billing     | Тариф и действующий доступ пространства; без подключения платёжного провайдера                                             | `Entitlements` блокирует и проверяет лимит до создания ресурса, `SubscriptionAccess` управляет доступом                              |

Межмодульные внешние ключи разрешены. Изменение каталога не переписывает снимки Practices; удаление исходных изображений, используемых снимками, блокируется ограничениями БД. Код другого модуля не должен импортировать внутренние Eloquent-модели или менять чужие таблицы.

### Контракты Media

`AssetStore::get()` возвращает `id`, `image_url`, `thumbnail_url`, `mime`, `width`, `height`, `bytes`, `original_filename`. Пакетный `getMany()` возвращает те же записи по ключам UUID. Доступ проверяется внутри Media, включая личное владение изображениями Sketchbook. Пути выдачи формирует сервер. `store(UploadedFile)` создаёт новый неизменяемый asset; `discardUnattached()` удаляет только неиспользуемый результат неудачной операции.

`originalData(id)` возвращает авторизованный оригинал как data URL для внутренних задач PDF и переносимого экспорта. Этот тяжёлый ответ не входит в DTO списков. `forDocument(assetId, documentId)` проверяет конкретный документ и право просмотра, включая выданный доступ. `AssetFingerprints::forMany(ids)` возвращает SHA-256 локальных оригиналов без выдачи их байтов. `PublishedImages::file(token, assetId)` разрешает только изображение из явного списка действующей публикации; возвращаемый локальный путь предназначен внутреннему контроллеру.

`AudioStore` — отдельный контракт с методами `limits`, `list`, `store`, `get`, `update`, `stream`. Он проверяет workspace и личного владельца, хранит кодек, длительность, SHA-256 и ревизию. Аудио проверяется через ffprobe/ffmpeg до сохранения и выдаётся с поддержкой Range; изображение не принимается за аудио. Архив доступен владельцу для прежней истории, но исключён из нового выбора. Публичная ссылка на практику не открывает личное аудио.

### Контракты Catalog и Collections

`AsanaReader::findMany(ids, includeArchived = false)` возвращает карточки по ключам UUID: название, другие названия, два варианта написания санскрита, категории/признаки, компактные ссылки вариантов, членство в подборках, личное избранное, изображение, ревизию и архивное состояние. Все запрошенные ID должны быть доступны; пропущенная или чужая карточка отклоняется. Внутри транзакции чтение удерживает разделяемую блокировку карточек. Workspace передавать от клиента нельзя: контекст определяется на сервере.

Списки каталога, палитры и `AsanaReader` выбирают только `CatalogReader::SUMMARY_COLUMNS`: native-исходник и JSON с шагами, подсказками, оборудованием, предосторожностями, адаптациями и редакционными сведениями не загружаются. Эти данные доступны при чтении одной карточки. Снимки практик также не содержат текущий исходник каталога.

`DrawingSources::validate(source, allowEmpty = false)` проверяет `ribka-drawing` версии 1/2. Пустой исходник разрешается явно только для листа Sketchbook. `PoseFacts::forImages([{asana_id, image_asset_id}])` возвращает ревизию классификации, анатомию и сложность по ключу точного текущего asset; несовпавшие исторические изображения пропускаются. `CatalogUsage::record(ids)` вызывается после успешной записи вставленных позиций, в общей транзакции: обновляет личное недавнее использование, сохраняя избранное.

`StarterLibrary` создаёт словарь нового пространства и копирует исходные карточки в два прохода: сначала новые UUID и изображения, затем отношения между скопированными карточками. Существующий каталог не перезаписывается. `IllustrationStyles` выбирает и создаёт неизменяемые представления для точного исходного изображения. `NativeVolumeRenderer` строит объём по координатам валидного native-рисунка, сохраняя его проекцию; условная глубина не выдаётся за восстановленную анатомию. Набор 23 октября включает все 261 карточку (186 активных, 75 архивных): 258 native и три архивных технических растровых дубля с проверенной точной обводкой. Для каждого доступны три персонажа с разной толщиной объёма. Прежний линейный стиль ограничен четырьмя проверенными рецептами. При отсутствии допустимой геометрии остаётся явный original.

Объёмные варианты `MODEL_REVISION=2` добавляются отдельными PNG 1024 × 1024 и строками `catalog_illustration_variants`. Геометрия и проверенные роли элементов связаны с хешами исходника; несовпадающий кеш отклоняется. Исходные карточки, native, изображения, снимки практик и исторические варианты не меняются. Консольный `ribka:warm-volume-variants` требует владельца и workspace, по умолчанию только проверяет набор; `--apply` создаёт недостающее, `--include-archived` не восстанавливает архив. Предпочтения и практики прогрев не меняет. Покрытие интерфейса считается отдельно для активных карточек и каждого стиля. Полный контракт и команды — [Illustrations/README.md](../app/Modules/Catalog/Illustrations/README.md).

`CollectionMembership::asanaIdsForSource(collectionId)` возвращает полный упорядоченный состав активной подборки своего пространства для общего запроса каталога. `addAsana` дополняет состав, `syncAsana` меняет активное членство без очистки архивных подборок, `collectionIdsForAsanas` читает активное членство. `lockWorkspace` и блокировки подборок защищают состав и ревизии при совместной транзакции с созданием/изменением карточки.

## HTTP

API владельца требуют авторизованного участника рабочего пространства. Используются cookie-сеанс, CSRF-защита при записи и JSON-ответы. Исключение — явно созданные ссылки `/p/{token}` и `/api/published/{token}/*`, ограниченные снимком публикации. Общий frontend-клиент — `resources/js/shared/api.ts`.

Создание и редактирование асаны имеют одинаковые поля: `name`, `aliases`, `sanskrit_cyrillic`, `sanskrit_latin`, `category_ids` личных категорий, `facet_assignments`, `collection_ids`, изображение/`drawing_source`, `steps`, `teacher_cues`, `equipment`, `precautions`, `adaptations`, `editorial`, `has_bind`, `classification_status`, `relations`. При создании название, изображение и активная подборка обязательны; при редактировании изображение необязательно, а `expected_revision` обязателен. Массивы/объекты multipart принимаются как JSON, `[]` очищает переданный список. Отсутствующие поля сохраняются. Исторический `description` остаётся совместимым полем API, но заметка карточки не возвращена в пользовательскую форму. Теги исключены из API и записи; исторические таблицы сохранены.

Личные категории остаются плоскими: `dimension` и `system_key` у них пусты. `/api/categories` возвращает их в `data` с `id`, `name`, `revision`, а отдельный `facets` — четыре группы системных значений. `category_ids` не может менять системные назначения. Создание личной категории принимает `name` до 100 символов; изменение и удаление требуют `expected_revision`. Подкатегории отклоняются с 422, используемую категорию нельзя удалить. Старые категории «Стоя», «Сидя», «Лёжа» сохранены как личные; совпадение имени не превращает их в системные значения.

## Классификация и жизненный цикл каталога

Миграция `000019` добавляет nullable `dimension`, стабильный `system_key` и отдельные назначения через существующую таблицу связей категорий. Словарь содержит 18 направлений, 15 зон тела, 9 положений и 3 уровня сложности. «Все»/«Любой» очищают фильтр, а не создают значение в БД. У сложности допустимо не более одного значения; у остальных групп — несколько. Словарь создаётся идемпотентно для новых пространств и при первом обращении к общему запросу/категориям прежнего пространства. Прежние UUID, названия и назначения не переписываются.

Фильтры `effect[]`, `anatomy[]`, `position[]`, `difficulty[]` принимают UUID значений. Внутри группы действует OR, между группами — AND. Поиск, личная категория, активная подборка, архив, избранное, недавнее использование, `has_bind` и оборудование применяются на сервере до пагинации. Счётчик значения — число различных карточек с учётом остальных групп и текущего источника; собственная группа исключается из условия подсчёта. Библиотека и все палитры используют один `CatalogQuery`.

| Действие                   | Признаки и отношения                                                                                        | Изображение/native-исходник                                                                               | Избранное и сохранённые листы                                       |
| -------------------------- | ----------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------- |
| Правка названия/описания   | Отсутствующие поля и назначения сохраняются; ревизия увеличивается                                          | Текущее изображение и исходник сохраняются                                                                | Снимки листов неизменны                                             |
| Правка `category_ids`      | Меняет только личные категории                                                                              | Без изменений                                                                                             | Без изменений                                                       |
| Правка `facet_assignments` | Отсутствующие группы сохраняются; переданный пустой массив очищает свою группу                              | Без изменений                                                                                             | Старые планы выполнения не переклассифицируются                     |
| Массовая классификация     | Явный append/replace, предпросмотр, подтверждение ручной проверки, CAS всех карточек и optional asset guard | Изображение не меняется                                                                                   | Прежние категории и снимки сохраняются                              |
| Сохранение рисунка         | Остальные поля сохраняются по тем же правилам                                                               | Новый PNG 1024 × 1024 и валидный source записываются атомарно; точный asset закрепляется в `NativeImages` | Ранее использованные assets/source остаются                         |
| Обычная замена файла       | Отсутствующие признаки и связи сохраняются                                                                  | Новый asset, текущий `drawing_source=null`                                                                | Прежние снимки продолжают ссылаться на старый asset                 |
| Новый вариант/дубликат     | Новая карточка копирует справочные поля и назначения, получает связь `variation` с исходной                 | Новое изображение и скопированный валидный source                                                         | Личное избранное не переносится; исходная карточка/листы неизменны  |
| Архив/восстановление       | Сохраняет назначения и отношения, повышает ревизию                                                          | Файлы и source сохраняются                                                                                | Не удаляет снимки; новую архивную карточку нельзя вставлять         |
| Избранное/недавнее         | Личная запись `workspace + user + asana`                                                                    | Без изменений                                                                                             | Не повышает общую ревизию карточки и не меняет других пользователей |
| Новый каталог пространства | Системные признаки сопоставляются по ключам; связи копируются вторым проходом                               | Копии сохраняют редактируемые исходники                                                                   | Существующий каталог не перезаписывается                            |

Отношения имеют виды `simpler`, `harder`, `preparation`, `follow_up`, `compensation`, `variation`; цель обязана быть другой карточкой своего пространства. Новая архивная цель запрещена, прежняя сохранённая связь с архивом не теряется. Классификация `reviewed` требует всех четырёх групп, неполная карточка остаётся `partial`/`unreviewed`. Изображение и название сами по себе не назначают сложность или анатомию.

Служебные команды безопасны по умолчанию: `ribka:seed-taxonomy` показывает число пространств с каталогом, `--apply` добавляет словарь и пересчитывает производный поисковый индекс без изменения ревизий. `ribka:classify-asanas` читает проверенный манифест и делает предпросмотр; запись требует `--apply`, workspace и аккаунт владельца. `ribka:pin-native` аналогично закрепляет точные текущие исходники, включая архив, без изменения карточек/снимков. Его применение проверяет неизменность source и SHA-256 конкретного PNG. `ribka:enrich-references` дополняет пустые шаги/подсказки по точному asset и ревизии, сохраняет прежнюю редакционную заметку, отказывается заменять авторскую справку и распознаёт точный повтор. Методическая проверенность всегда остаётся `false`. Ни одна из команд не классифицирует по совпадению названий.

Списки Practices принимают `kind=practice|template|fragment`, `q`, `archive=active|archived`, `folder_id`, `include_cycle_documents`, `page`, `per_page` и `sort=updated_desc|updated_asc|title_asc|title_desc|created_desc|created_asc`. Строки используют `kind=row|transition`. Ответ: `{data, current_page, last_page, total}`. Элемент содержит ревизию, количество/превью ячеек и рассчитанную длительность, если у всех заполненных ячеек она известна; документ также содержит число блоков/строк, ссылки циклов и активные личные папки. Уровень — наибольшая закреплённая сложность только при полной разметке всех заполненных позиций, иначе `null`. Текущая классификация каталога для этого не подставляется. Сортировка и вид карточки/список восстанавливаются из URL.

Чтение и запись одного объекта возвращают `{data: object}`. Создание практики принимает `title`, необязательные `theme`, `note`, `practice_date`, `kind` и `template_id`. Без шаблона создаются пять блоков, в каждом одна строка по шесть пустых ячеек.

Сохранение документа передаёт `expected_revision`, метаданные и всё дерево `blocks → rows → cells`. У каждого элемента есть UUID; порядок задаётся массивом. Ячейка передаёт `id`, `card_snapshot_id`, `custom_name`, `group_key`, `arrow_direction`, `note` и параметры выполнения: `advance_mode=manual|time|breaths`, `duration_seconds`, `breath_count`, `repetitions`, `side`, `side_order`. Она содержит либо снимок асаны, либо собственное название без изображения (до 160 символов); одновременно оба запрещены. Пустая ячейка сохраняет структуру, группу и стрелку. Заметки строки и подписи ячеек отделены от скрытых исторических `note`/`practice_date` самого документа.

Списки дополнительно возвращают `filled_cell_count` (ячейки со снимком или своим названием), `custom_cell_count` и `preview_cells` — первые четыре заполненные ячейки в порядке документа. `preview_cards` остаётся списком только снимков с изображениями для совместимости.

Новый снимок карточки закрепляет `classification_snapshot`: ревизию каталога,
анатомические признаки и сложность для точного исходного изображения или его
проверенного варианта. Это данные снимка, а не текущая разметка каталога.
Копирование и смена оформления сохраняют их; явное обновление из библиотеки
создаёт новый снимок. Прежние `NULL` не заполняются миграцией. Для них план
владельца может получить факты только при точном текущем изображении либо
варианте с тем же текущим источником. Историческое несовпадение остаётся
неклассифицированным. Чтение ревизии и признаков каталога согласовано блокировкой.

Сохранение строки передаёт `title`, `theme`, `note`, `cells`, а при изменении — `expected_revision`. Создание строки всегда назначает новые UUID её ячейкам. Архивирование и восстановление требуют `expected_revision`; копирование принимает её для проверки актуальности источника.

## Группы ячеек

`group_key` — nullable UUID, локальная метка группы внутри строки, без отдельной сущности и внешнего ключа. Две и более соседние ячейки с одинаковым ключом составляют одну группу, которая отображается скобками. В одной строке допускаются несколько групп; пересечения и вложенность невозможны, потому что ячейка хранит только один ключ. Сервер отклоняет одиночные и разорванные группы с HTTP 422. Проверка выполняется отдельно для каждой строки и сохранённого шаблона строки.

Группа объединяет позиции. В ней допустимы картинки, свои названия и пустые ячейки. Очистка или замена содержимого не меняет `group_key`. Для снятия группы клиент явно передаёт `group_key=null` у её ячеек. После удаления позиций клиент должен явно снять оставшуюся одиночную группу или скорректировать группировку.

При копировании практики, шаблона или строки структурные UUID меняются, а значения `group_key` сохраняются. Одинаковый ключ в разных строках обозначает независимые группы. `group_key` не записывается в реестр `practice_entity_ids` и не проверяется на глобальное владение.

Совместимость со старым клиентом: если `group_key` отсутствует, обновление восстанавливает текущую принадлежность по стабильному ID ячейки этого документа/шаблона строки. Неизвестная новая ячейка получает `null`. При создании локальной копии или сохранённой строки сервер также пытается восстановить пропущенную метку по исходному ID доступной ячейки в текущем пространстве перед генерацией новых ID. Если изменение структуры после такого восстановления разрывает группу или оставляет одну ячейку, запись отклоняется; существующая группировка не снимается молча. Для полностью новых ID восстановить неизвестную клиенту группировку невозможно, поэтому актуальный клиент всегда передаёт поле явно.

Миграция `000008` только добавляет nullable `group_key` в `practice_cells` и `practice_row_template_cells`. У существующих ячеек начальное значение `null`; содержимое и ревизии документов при миграции не изменяются.

## Целостность и конфликты

- Запись документа выполняется в транзакции с блокировкой родительской записи, проверкой ревизии и единым обновлением всего дерева. Чтение полного документа удерживает блокировку до получения всех частей, поэтому ревизия соответствует дереву.
- При несовпадении ревизии возвращается HTTP 409 и `current_revision`. Автосохранение должно остановиться; пользователь выбирает новую копию своего локального дерева либо загрузку актуального документа.
- Все UUID и снимки проверяются на принадлежность пространству и документу. В `practice_entity_ids` сохраняется принадлежность удалённых структурных UUID: undo может вернуть их в исходный документ, но другой документ не может присвоить их себе.
- `copy-local`, копирование практики и вставка шаблона назначают новые UUID структуры, сохраняя ссылки на immutable snapshots. Изменение источника не влияет на полученную копию.
- Архивирование увеличивает ревизию. Сохранение архивного документа запрещено до восстановления.
- Снимки создаются из доступных активных карточек Catalog; архив исходной асаны не мешает показывать старые листы, отменять действия и копировать шаблоны.
- Ограничения структуры находятся в `config/sequence.php`: 20 блоков, 20 строк в блоке, 12 ячеек в строке, максимум 1000 ячеек на документ.

## Циклы, папки и переиспользование

Цикл и шаблон цикла содержат 1–52 упорядоченные позиции. Создание из практики и
дублирование копируют дерево каждого занятия, а не оставляют редактируемую ссылку
на исходник. Изменение структуры проверяет ревизию цикла; для удаления заполненной
позиции требуется явный выбор: оставить занятие отдельно либо архивировать его.
Замена позиции создаёт новую копию и сохраняет прежний документ. Create, duplicate,
structure, replace, insert и undo используют ключ операции с проверкой владельца,
типа запроса и его данных: повтор не создаёт вторую копию.

Папки документов — личные связи many-to-many. Архив папки не архивирует и не
удаляет практику. Фрагмент — отдельный документ `kind=fragment` с
`fragment_kind=block|sequence`; строки и связки хранятся в `practice_row_templates`
с `kind=row|transition`. Вставка использует новые структурные UUID и прежние
неизменяемые снимки, сохраняя позиционные группы, стрелки и параметры выполнения.

## Рисовалка и Sketchbook

`ribka-drawing` хранит размеры 1024 × 1024, элементы и версию. Версия 1 остаётся
совместимой; версия 2 допускает необязательный цвет `#rrggbb` и плоский
`group_id` элементов. Группа должна содержать минимум два элемента. Ограничения
проверяются сервером: до 1000 элементов, 50 000 точек и 4 МБ JSON. Группы элементов
не связаны с `group_key` ячеек практики. Масштаб интерфейса не меняет размеры PNG.

Выделение прямоугольником/лассо и общие преобразования работают через одну историю
рисования. `AsanaDrawing.exportDrawing()` возвращает PNG/native без события
применения; `exportSelection()` переносит выделенное в нормализованный квадратный
PNG/native. Доступны цвета, группировка, общий поворот/масштаб/перенос, отражение,
копия и удаление. Черновики разделены по workspace, пользователю и контексту.

Sketchbook хранит личные листы `square`, `a4-portrait`, `a4-landscape`, их
ревизии, PNG и редактируемый исходник. Список не выдаёт исходники; чтение одного
листа проверяет личного владельца. Сохранение проверяет CAS; старый asset остаётся
закреплён за тем же владельцем даже после замены изображения. `SketchImages`
проверяет все такие изображения при обычном чтении Media. Копия листа получает
независимый UUID. Для пустого листа разрешён пустой исходник, для карточки каталога
и переносимой фигуры — нет.

`Practices\PublicApi\NativeImages` хранит source и SHA-256 для конкретного
неизменяемого asset. Повтор с другим source/PNG отклоняется. `DrawingSnapshots`
создаёт снимок самостоятельной фигуры без `source_asana_id`; повтор UUID проверяет
название и source. Фигура не становится карточкой каталога автоматически.

## Выполнение и личная история

Sessions использует `/api/executions/plan/{id}`, `/api/executions` и
`PUT /api/executions/{id}`. План строится только через `ExecutionDocuments` с
проверкой собственного/предоставленного доступа и ревизии. В начале сохраняется
снимок плана: порядок, картинки, название, стороны, повторы, время/дыхание и
доступные факты анатомии для точного asset. Изменение каталога или практики не
переписывает начатую историю. Пустые ячейки пропускаются, текстовые входят в план.

Сессии принадлежат workspace и пользователю. Сервер проверяет ревизию, диапазон
шага, монотонность времени и соответствие прошедшему времени. Завершённая либо
прерванная запись не начисляет время повторно. История показывает календарь и
секунды по сохранённым анатомическим признакам; неизвестные изображения остаются
«без классификации». Это история управляемой сессии, не медицинская оценка.
CSV выгружается отдельно из `/api/executions/export`. Публичный проигрыватель
использует план публикации; личная серверная история требует входа.

Meditation имеет независимые настройки, сессии, календарь и CSV. Сессия фиксирует
настройки при старте. Активное время подтверждается короткой серверной арендой,
пауза его не увеличивает. История и личное аудио не публикуются вместе с листом.
Готовые фоновые звуки и сигналы — собственный процедурный синтез Web Audio;
происхождение указано в `resources/js/modules/meditation/soundManifest.ts`.
Подробные параметры аудио и аренды — `app/Modules/Meditation/README.md`.

## Просмотр, PDF и перенос

`/practices/{id}/preview` открывает готовый лист, `/practices/{id}/print` готовит его и автоматически вызывает диалог печати. Повторно используется `SequencePreview.vue`. Печать ждёт загрузки шрифтов и декодирования всех изображений; при ошибке доступна повторная загрузка.

Пустые ячейки сохраняют место. Группы печатаются чёрными скобками, межклеточные
знаки остаются между изображениями, S/звезда — у соответствующей фигуры. При
отключённых названиях скрыты подписи к картинкам и пояснения, остаются рисунки,
скобки и обозначения; текстовая ячейка сохраняет своё название. Скрытые значения
не удаляются из БД.

Серверный лист и скачиваемый PDF используют один `SheetRenderer`. Доступны A4
portrait/landscape и пресеты `clean`, `names`, `teach`. В `clean` названия
принудительно выключены. PDF создаётся Dompdf с встроенными изображениями и
кириллическим шрифтом, без внешних сетевых ресурсов, PHP или JavaScript. Чтение
оригиналов ограничено 48 МБ на PDF; слишком большой лист возвращает 422 с
предложением печати браузера. Настройки вывода личные и защищены ревизией.
Браузерная печать остаётся отдельным доступным действием.

Переносимый JSON содержит независимое дерево, снимки, встроенные изображения с
контрольными суммами, необязательную закреплённую классификацию каждого снимка
и native-исходники для точных assets. Классификация проверяется по ограниченной
схеме и сохраняется при импорте без привязки к чужой карточке каталога. Сначала
выполняется предпросмотр, затем явный импорт с ключом операции. Импорт создаёт
копию, не меняет существующий документ по полученному UUID. По совпадению имени
или текущей карточки исторический source не подставляется.

Публикация создаёт неизменяемый снимок явно выбранной ревизии и список доступных
изображений. Случайный токен, срок действия и отзыв проверяются при каждом чтении
страницы, плана и медиа. Публикация не выдаёт workspace, email, личную историю,
аудио или исходники рисования. Разрешение копирования задаётся явно; само открытие
ссылки не создаёт документ у читателя. QR содержит адрес этой же ссылки.

## Эксплуатация

Точный порядок локального запуска приведён в корневом README. Docker Compose содержит PHP-приложение, Nginx и PostgreSQL; frontend собирается Vite. Данные БД находятся в именованном Docker-volume, приватные изображения — в storage проекта. Остановка контейнеров без удаления volumes сохраняет данные.

Рабочее пространство и отдельные аккаунты создаются командами `ribka:workspace`, `ribka:member`; пароль меняется через `ribka:password`. Пароли вводятся скрыто и не записываются в репозиторий.

Резервная копия должна включать дамп PostgreSQL, приватный storage и безопасно сохранённую конфигурацию приложения. Дамп без файлов не восстанавливает изображения. Не применять `migrate:fresh`, `docker compose down -v` или очистку storage к среде с нужными данными.

Автоматические тесты не создаются по правилам проекта. Проверки: PHP-синтаксис, Pint, типы Vue/TypeScript, production build, список маршрутов, миграции и ручные пользовательские сценарии.
